# 아침 첫 채팅 브리핑

## 실행 조건

- Asia/Seoul 기준 오전 8시 이후 들어온 그날의 첫 일반 사용자 메시지에 실행한다.
- `private/morning-brief-state.json`의 `last_report_date`가 오늘이면 실행하지 않는다.
- 예약 자동화·heartbeat 실행과 자동화 관리 요청에는 적용하지 않는다.
- 사용자가 `질문 답변 계속`이라고 입력한 경우에는 보고를 반복하지 않고 직전 보류 요청을 처리한다.

## 처리 방식

1. 첫 메시지의 원래 요청을 대화 맥락에 보존하고 아직 답하지 않는다.
2. Google Calendar에서는 일정의 상세 의미보다 오늘의 busy 시간을 확인한다.
3. Notion 개인 할 일·프로젝트, 취준 일정과 지원 현황을 확인한다.
4. 현실적인 아침 보고를 제공하고 로컬 상태의 날짜와 시각을 갱신한다.
5. 답변 마지막에 `질문 답변 계속`을 입력하면 원래 요청을 이어서 처리한다고 안내한다.

## 보고 형식

- 오늘의 취준 가능시간
- 반드시 끝낼 작업 1~3개와 선정 이유
- 시간이 남을 때 할 작업
- 일정 충돌이나 가용시간 부족으로 미룰 작업
- 가장 가까운 지원·면접 마감과 필요한 선행 작업

가용시간보다 많은 작업을 배정하지 않는다. 개인 일정의 제목·참석자·장소 등 상세 내용은 꼭 필요한 경우가 아니면 노출하지 않는다.
