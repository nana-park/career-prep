# ChatGPT Work 히스토리 조회 규칙

## 기본 원칙

- Work 프로젝트의 과거 대화는 자동 컨텍스트가 아니라 필요할 때 선택적으로 확인하는 보조 근거다.
- 현재 요청과 제공된 자료만으로 판단할 수 있으면 과거 대화를 조회하지 않는다.
- 전체 프로젝트를 매번 읽지 않고 제목·요약·수정 시각으로 후보를 좁힌 뒤 필요한 대화만 읽는다.
- 원문 전체를 복사해 보관하지 않고 재사용 가능한 판단과 최신성 정보만 로컬 소스 원장에 기록한다.

## 반드시 조회하는 경우

- 사용자가 이전 Work 논의나 특정 과거 대화를 기준으로 요청한다.
- 기존 지원서의 컨셉·판단·첨삭 맥락을 이어가야 한다.
- 현재 입력만으로 경험의 역할, 의사결정, 성과 또는 이전 선택 이유를 확정할 수 없다.
- 저장된 판단과 현재 설명이 충돌한다.

## 조회하지 않는 경우

- 단순 문구 수정, 맞춤법 교정 또는 형식 변경이다.
- 현재 대화에 필요한 사실과 기준이 충분하다.
- 동일 주제의 관련 대화를 이미 읽었고 해당 대화의 수정 시각이 변하지 않았다.
- 과거 논의가 이번 회사·공고·문항의 판단에 영향을 주지 않는다.

## 조회 순서

1. `sources.local.yaml`에서 Work 프로젝트 ID를 확인한다.
2. `source-ledger.local.yaml`에서 같은 주제의 기존 조회 기록을 찾는다.
3. 프로젝트 대화 목록의 `updated_at`과 원장에 기록된 값을 비교한다.
4. 변경이 없고 현재 요청과 판단 범위가 같으면 `stable_findings`를 재사용한다.
5. 변경됐거나 근거 범위가 달라졌으면 관련 대화만 읽고 원장을 갱신한다.
6. 사실관계가 필요한 경우 Work 대화만 믿지 않고 Drive 원본과 교차 확인한다.

## 원장 기록 기준

- 주제, 대화 ID, 제목, 마지막 확인 시각, 대화 수정 시각을 기록한다.
- 반복 활용할 수 있는 판단만 `stable_findings`에 짧게 요약한다.
- 지원자 개인정보, 대화 원문, 회사 내부 정보, 지원서 전체 문장은 기록하지 않는다.
- 새 공고나 회사에 그대로 적용할 수 없는 판단에는 적용 범위를 명시한다.
