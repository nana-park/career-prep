# Career Prep

AI PM 취업준비의 운영 원칙과 반복 워크플로를 관리하는 저장소입니다. 개별 실행 능력은 별도의 [`skills`](https://github.com/nana-park/skills) 저장소에서 관리하고, 이 저장소는 어떤 상황에서 어떤 스킬과 소스를 사용할지 조정합니다.

## 최종 목표

사용자를 서류와 면접에서 통과시켜 대기업의 목표 직무에 최종 합격시키고 입사까지 연결합니다. 문서 작성은 목적이 아니라 채용 퍼널을 통과하기 위한 수단입니다.

## 운영 조직

### PM팀

10년 차 Product Manager 수준의 관점으로 실제 경험과 제품·기술 판단을 검증합니다.

- 제품 문제, 사용자 가치, 사업 영향과 본인의 판단을 발굴
- 시스템 구조, 데이터 흐름, 모델 동작, API 연동과 운영 제약 검토
- 대안, 트레이드오프, 의사결정 기준과 실제 기여 구분
- 기술·제품 면접에서 검증될 약한 인과관계와 반문 점검

| 배정 스킬 | 역할 |
|---|---|
| `pm-experience-mentor` | 경험 발굴, 실제 기여와 제품 판단 복원, 직무 역량으로 재해석 |

### 커리어 컨설턴트팀

7년 차 커리어 컨설턴트 수준의 관점으로 채용시장과 전형별 설득 전략을 설계합니다.

- 회사·공고·직무와 채용 단계별 평가 논리 해석
- 이력서, 경력기술서, 포트폴리오와 자기소개서의 포지셔닝 통합
- 예상 질문, 답변 구조, 전달 방식과 면접 리스크 점검
- 지원 결과를 바탕으로 공고 선택과 준비 우선순위 조정

| 배정 스킬 | 역할 |
|---|---|
| `job-posting-signal-analyzer` | 여러 공고의 반복 요구역량, 변화와 준비 갭 분석 |
| `pm-drama-upgrade-mentor` | 특정 공고·문항의 핵심 주장, 지원서 컨셉과 설득력 고도화 |

### 팀 간 협업

1. 커리어 컨설턴트팀이 현재 채용 퍼널의 병목과 평가 기준을 정의합니다.
2. PM팀이 이를 증명할 실제 경험과 제품·기술 판단을 검증합니다.
3. 두 팀이 이번 지원에서 기억되어야 할 하나의 핵심 주장을 합의합니다.
4. 지원 문서와 면접 답변을 같은 근거와 포지셔닝으로 연결합니다.
5. 지원 결과와 면접 피드백을 다음 전략에 반영합니다.

두 팀의 판단이 충돌하면 사실 정확성과 검증 가능성을 먼저 지키고, 그 범위 안에서 채용 설득력이 가장 높은 선택을 합니다.

## 역할 분리

- `career-prep`: 취업준비 원칙, 소스 정책, 스킬 라우팅, 반복 작업 정의
- `skills`: 여러 도메인에서 재사용 가능한 개별 Codex 스킬
- Notion: 공고, 지원 상태, 일정의 운영 데이터
- Google Drive: 경력·프로젝트 원본
- 로컬 취업준비 폴더: 작업본, 제출본, 분석 결과

팀 구성, 스킬 배정 또는 협업 방식이 변경되면 이 README의 `운영 조직`을 가장 먼저 갱신합니다. 세부 문서는 README와 모순되지 않도록 함께 수정합니다.

## 사용 방식

1. [최종 목표와 운영팀](./docs/GOAL_AND_TEAM.md)을 기준으로 현재 채용 퍼널의 병목을 판단합니다.
2. 요청이 사용자 경험에 관한 것인지, 공고 시장 분석인지, 특정 지원서 작성인지 분류합니다.
3. [스킬 라우팅](./docs/SKILL_ROUTING.md)에 따라 필요한 스킬만 불러옵니다.
4. 경험 사실이 필요하면 Drive 원문을 읽고, 공고 분석이면 Notion DB를 읽습니다.
5. 원본과 개인 데이터는 이 저장소에 복사하지 않습니다.

## 로컬 소스 연결

`sources.example.yaml`을 구조 기준으로 사용하고, 실제 URL과 프로젝트 식별자는 Git에서 제외되는 `sources.local.yaml`에 둡니다. 작업을 시작할 때 `sources.local.yaml`이 있으면 이 파일을 우선 읽습니다.

Work 프로젝트의 과거 대화는 매번 읽지 않습니다. [Work 히스토리 조회 규칙](./docs/WORK_HISTORY.md)에 따라 현재 입력으로 부족할 때만 관련 대화를 확인하고, 조회 결과의 최신성은 Git에서 제외되는 `source-ledger.local.yaml`로 관리합니다.
