# Career Prep

AI PM 취업준비의 운영 원칙과 반복 워크플로를 관리하는 저장소입니다. 개별 실행 능력은 별도의 [`skills`](https://github.com/nana-park/skills) 저장소에서 관리하고, 이 저장소는 어떤 상황에서 어떤 팀이 어떤 스킬과 소스를 사용할지 조정합니다.

## 역할 분리

| 구성 요소 | 담당 역할 | 저장하는 내용 | 저장하지 않는 내용 |
|---|---|---|---|
| `career-prep` | 취업준비 전체 운영 | 최종 목표, 팀 구조, 소스 정책, 스킬 라우팅, 반복 워크플로 | 개인 원문, 비공개 링크, 지원서 제출본 |
| [`skills`](https://github.com/nana-park/skills) | 재사용 가능한 실행 능력 | 개별 Codex 스킬과 일반화된 행동 규칙 | 특정 지원자의 상태와 비공개 원문 |
| Notion | 채용·할 일 운영 데이터 | 공고, 지원 현황, 일정, 개인 할 일과 프로젝트 | 스킬 구현과 원본 경력 자료 |
| Google Calendar | 실제 가용시간 판단 | 개인 일정의 busy 시간과 일정 충돌 | 불필요한 사생활 내용의 수집·평가 |
| Google Drive | 사실관계의 원본 | 경력, 프로젝트, 포트폴리오와 참고 자료 | 운영 규칙과 스킬 코드 |
| ChatGPT Work | 과거 판단과 대화 맥락 | `지원서 커스텀` 프로젝트의 기존 논의 | 상시 자동 주입되는 전체 히스토리 |
| 로컬 취업준비 폴더 | 실제 작업 공간 | 작업본, 제출본, 분석 결과와 비공개 연결 설정 | 공개 저장소에 올릴 수 없는 자료의 외부 공유 |

팀 구성, 스킬 배정 또는 협업 방식이 변경되면 이 README의 `최강취업지원팀`을 가장 먼저 갱신합니다. 세부 문서는 README와 모순되지 않도록 함께 수정합니다.

## 최종 목표

사용자를 서류와 면접에서 통과시켜 대기업의 목표 직무에 최종 합격시키고 입사까지 연결합니다. 문서 작성은 목적이 아니라 채용 퍼널을 통과하기 위한 수단입니다.

## 1. 사용 방식

1. 최종 목표를 기준으로 현재 채용 퍼널의 병목을 판단합니다.
2. 요청이 경험 발굴, 시장·공고 분석, 특정 지원서 작성 또는 면접 준비 중 어디에 해당하는지 분류합니다.
3. `최강취업지원팀`에서 요청의 주관팀과 필요한 스킬을 배정합니다.
4. 경험 사실이 필요하면 Drive 원본을, 지원 상태와 일정이 필요하면 Notion을 확인합니다.
5. 이전 지원서 판단이 필요할 때만 ChatGPT Work 히스토리를 선택적으로 조회합니다.
6. 두 팀이 같은 근거와 포지셔닝으로 서류와 면접 답변을 연결합니다.
7. 지원 결과와 면접 피드백을 다음 공고 선택과 준비 전략에 반영합니다.

원본과 개인 데이터는 이 저장소에 복사하지 않습니다. 실제 소스 연결값과 조회 이력은 Git에서 제외되는 로컬 설정으로 관리합니다.

## 2. 최강취업지원팀

### PM팀

**팀장: 10년 차 Product Manager**

팀장은 실제 경험과 제품·기술 판단을 집요하게 검증하고, 팀원의 분석을 종합해 PM 관점의 최종 의견을 냅니다.

- 제품 문제, 사용자 가치, 사업 영향과 본인의 판단을 발굴
- 시스템 구조, 데이터 흐름, 모델 동작, API 연동과 운영 제약 검토
- 대안, 트레이드오프, 의사결정 기준과 실제 기여 구분
- 기술·제품 면접에서 검증될 약한 인과관계와 반문 점검

| 팀원 | 역할 |
|---|---|
| `pm-experience-mentor` | 경험 발굴, 실제 기여와 제품 판단 복원, 직무 역량으로 재해석 |

### 커리어 컨설턴트팀

**팀장: 7년 차 커리어 컨설턴트**

팀장은 채용시장의 평가 논리를 읽고, 팀원의 분석을 종합해 전형별 합격 전략과 준비 우선순위를 결정합니다.

- 회사·공고·직무와 채용 단계별 평가 논리 해석
- 이력서, 경력기술서, 포트폴리오와 자기소개서의 포지셔닝 통합
- 예상 질문, 답변 구조, 전달 방식과 면접 리스크 점검
- 지원 결과를 바탕으로 공고 선택과 준비 우선순위 조정

| 팀원 | 역할 |
|---|---|
| `job-posting-signal-analyzer` | 여러 공고의 반복 요구역량, 변화와 준비 갭 분석 |
| `pm-drama-upgrade-mentor` | 특정 공고·문항의 핵심 주장, 개인 후킹 서사, 지원서 컨셉과 설득력 고도화 |

### 팀 간 협업

1. 커리어 컨설턴트팀장이 현재 채용 퍼널의 병목을 정의하고 필요한 팀원을 배정합니다.
2. PM팀장이 이를 증명할 경험 범위를 정하고 `pm-experience-mentor`의 발굴 결과를 검증합니다.
3. 각 팀장이 팀원의 결과를 종합해 이번 지원에서 기억되어야 할 하나의 핵심 주장을 합의합니다.
4. 지원 문서와 면접 답변을 같은 근거와 포지셔닝으로 연결합니다.
5. 지원 결과와 면접 피드백을 다음 전략에 반영합니다.

두 팀의 판단이 충돌하면 사실 정확성과 검증 가능성을 먼저 지키고, 그 범위 안에서 채용 설득력이 가장 높은 선택을 합니다.

## 로컬 소스 연결

`sources.example.yaml`을 구조 기준으로 사용하고, 실제 URL과 프로젝트 식별자는 Git에서 제외되는 `sources.local.yaml`에 둡니다. 작업을 시작할 때 `sources.local.yaml`이 있으면 이 파일을 우선 읽습니다.

Work 프로젝트의 과거 대화는 매번 읽지 않습니다. [Work 히스토리 조회 규칙](./docs/WORK_HISTORY.md)에 따라 현재 입력으로 부족할 때만 관련 대화를 확인하고, 조회 결과의 최신성은 Git에서 제외되는 `source-ledger.local.yaml`로 관리합니다.
